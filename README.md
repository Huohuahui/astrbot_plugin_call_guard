# astrbot_plugin_call_guard

**单人刷屏静默防护** —— 有人狂 call 你的机器人？不用再靠全局限速误伤所有人：call_guard 会自动把刷屏的人拉进静默期，期间按你设定的概率偶尔回复，其余消息直接丢弃、不消耗 token。

> 一句话：**限全局的是闸门，限单人的是 call_guard。**

## 它解决什么问题

AstrBot 自带的 `platform_settings.rate_limit` 是全局限速——一个人刷屏，全群都被限。call_guard 把防护粒度做到**单个用户**：

- 群友 A 120 秒内艾特/回复机器人 5 次 → A 进静默期 600 秒
- 静默期内 A 再 call：20% 概率正常回复（显得"还在，但不想理你"），80% 直接丢弃
- **被丢弃的消息不进 LLM，token 零消耗**
- 其他人聊天完全不受影响

## 特性

- 🎯 **精准到人**：只静默刷屏者，不误伤正常群友
- 🔢 **概率可调（0-1）**：0 = 静默期完全不理，1 = 照常回复，中间值模拟"若即若离"
- 🛡️ **管理员豁免**：管理员不计入统计、永不触发（可关闭豁免）
- ⌨️ **指令放行**：`/` 开头的指令消息不计数也不拦截，天气、群分析等指令不受影响
- 💾 **状态持久化**：静默状态落盘 `data/plugin_data/call_guard/state.json`，重启不丢、不重复计数
- 📦 **零依赖**：纯 AstrBot API 实现，无第三方库，装完即用
- 🔇 **静默无感**：被静默不提示、不@、不举报，机器人只是"安静了"

## 工作原理

```
群消息进入
   │
   ├─ 是 "/" 指令？ ──→ 直接放行（不计数）
   │
   ├─ 是私聊？ ──→ 不管，放行
   │
   ├─ 发送者是管理员或在豁免名单？ ──→ 放行
   │
   ├─ 消息里艾特了机器人 或 回复了机器人的消息？
   │       │
   │       ├─ 否 → 放行（普通群聊不计数）
   │       │
   │       └─ 是 → 计入该用户在窗口期内的 call 计数
   │               │
   │               ├─ 已在静默期？ → 按 reply_probability 概率放行，否则 stop_event 丢弃
   │               │
   │               └─ 窗口内达到 call_limit？ → 进入 silence_seconds 静默期
   │
   └─ 其他消息 → 正常走 AstrBot 管线
```

## 安装

### 方式一：插件市场（推荐）

AstrBot WebUI → 插件管理 → 从插件市场安装，搜索 `call_guard`。

> 上架插件市场审核中，也可通过「从 GitHub 仓库安装」填入本仓库地址安装。

### 方式二：从 GitHub 仓库安装

AstrBot WebUI → 插件管理 → 从仓库安装，填入：

```
https://github.com/Huohuahui/astrbot_plugin_call_guard
```

### 方式三：手动安装

把本仓库克隆/下载到 AstrBot 的 `data/plugins/astrbot_plugin_call_guard/` 目录，重启 AstrBot。

## 配置项

安装后在 WebUI 插件面板可视化配置：

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `enable` | bool | `true` | 总开关 |
| `scope_groups` | list | `[]` | 生效群列表，留空 = 所有群聊生效 |
| `window_seconds` | int | `120` | 计数窗口（秒） |
| `call_limit` | int | `5` | 窗口内 call 达到该次数触发静默 |
| `silence_seconds` | int | `600` | 静默时长（秒） |
| `reply_probability` | float | `0.2` | 静默期内回复概率（0-1） |
| `exempt_admins` | bool | `true` | 管理员豁免 |
| `exempt_users` | list | `[]` | 豁免用户 QQ 号列表 |

**`reply_probability` 怎么选：**

| 值 | 效果 |
|---|---|
| `0` | 静默期完全不理（最省 token） |
| `0.1 ~ 0.3` | 偶尔回一下，像"在线但不想聊"（推荐） |
| `0.5+` | 约半数回复，威慑力弱 |
| `1` | 等于只统计不拦截（调试用） |

## "call 机器人"的判定

以下两种消息算一次 call：

1. 消息里 **@了机器人**
2. 消息是**对机器人消息的引用回复**

普通群聊（哪怕提到机器人的名字）不算 call，不会误伤。

## 与其他插件的兼容

- **优先级 99998**：低于管理类拦截插件（如 admin_commander 的 100000），老板指令台先处理，本插件不抢
- 对后续所有插件的指令（天气、群分析等以 `/` 开头的消息）完全放行
- 丢弃动作通过 `event.stop_event()` 实现，被丢弃的消息不进任何后续处理

## 常见问题

**Q：被静默的人会收到提示吗？**
不会。没有任何提示消息，机器人只是对该用户"偶尔回复/不回复"。

**Q：静默期内他换一种方式说话（不艾特不回复）能绕过吗？**
能——普通群聊本来就不算 call，这是设计如此：插件只防护"骚扰式 call"，不限制正常聊天。

**Q：和 AstrBot 自带的 rate_limit 什么关系？**
互不冲突，但建议二选一。全局 rate_limit 误伤所有人，call_guard 精准限人；用 call_guard 的话可以把 rate_limit 关掉。

**Q：重置某个人的计数/静默？**
删除 `data/plugin_data/call_guard/state.json` 里对应的 `群号:QQ号` 键，或直接删文件后重启 AstrBot。
